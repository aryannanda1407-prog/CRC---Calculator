CRC CALCULATOR

Cyclic Redundancy Check — Error Detection System

When data travels over a network, noise can flip some of its bits. CRC adds a short check value to the data before it is sent. The receiver recalculates that value and can tell, with very high probability, whether the data was damaged on the way.

At least 2 bits, and it must start with 1. Example: 1101 means x³ + x² + 1.

How CRC Works

        
Six steps, from the sender's data to the receiver's check.


        
    
          
  1. 1
    Enter the original binary data.
    This is the message the sender wants to transmit, for example 100100.
    2. 
          
  2. 2
    Append zeros to the data.
    Add as many zeros as the generator length minus one. A 4-bit generator adds 3 zeros.
    3. 
          
  3. 3
    Perform modulo-2 division using XOR.
    Whenever the leading bit is 1, XOR with the generator. Otherwise XOR with zeros. Then shift left and bring down the next bit.
    4. 
          
  4. 4
    Obtain the CRC remainder.
    The bits left after the last step are the CRC. It is always generator length minus one bits long.
    5. 
          
  5. 5
    Append the remainder to create the transmitted data.
    Replace the appended zeros with the CRC: original data + CRC.
    6. 
          
  6. 6
    The receiver divides the received data to check for errors.
    Divide by the same generator. A remainder of all zeros means no error was detected. Any 1 means the data was damaged.

XOR and modulo-2 division

        
XOR (exclusive OR) outputs 1 only when its two input bits are different. It is addition without a carry.

        

          
ABA XOR B

          
            
000

            
011

            
101

            
110

          
        

        
Modulo-2 division is ordinary long division where every subtraction is replaced by XOR. Because there are no borrows or carries, it is very cheap to build in hardware, which is why networks use it.

        
CRC can detect errors but cannot correct them. If an error is detected, the data is normally re-sent.

      


      

        
Corrections made while porting from C++

        
    
          
  • Data length check. The C++ code required the data to be at least as long as the generator, even when generating a CRC. That wrongly rejects valid input such as data 1 with generator 1011, because the zeros are appended before dividing. The web version only requires non-empty data when generating, and requires received data of at least generator length when verifying.
    • 
          
  • Input cleaning. Spaces typed around or inside the binary strings are removed automatically (C++ cin stops reading at the first space).
    • 
          
  • Menu input. The C++ menu loops forever if a letter is typed instead of a number. The web buttons avoid this entirely.
    • 
          
  • Unchanged and verified. The division loop itself (XOR when the leading bit is 1, drop the first bit, bring down the next) is correct and was ported as-is.
